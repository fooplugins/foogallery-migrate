## Further low-risk fixes

- Replaced three `parse_url()` calls with `wp_parse_url()`. All three migration
  forms retain their default URL if the posted URL is absent or an array, and
  reject non-scalar posted page numbers. Gallery/album rendering no longer reads
  an absent referrer query, and page zero becomes page one. Existing positive
  page selection and bounded repository reads are preserved.
- Used `wp_rand()` rather than `mt_rand()` for the inactive image-tag queue's
  ownership marker. Its SHA-256 shape and persisted ownership protocol remain
  unchanged. This is hardening, not evidence that the previous marker enabled
  unauthorized access.
- Used `gmdate()` for numeric WP Photo Album Plus timestamps, avoiding process
  timezone shifts. Valid EXIF wall-clock strings and invalid-date rejection are
  unchanged. This matches the previous output under WordPress's default UTC
  process timezone; it does not reinterpret EXIF strings as UTC.
- Used `wp_delete_file()` in all three failed image-copy/sideload cleanup paths,
  honoring WordPress's deletion filter. Only the existing temporary-copy path
  is passed to it; the original source file is retained. No dependency on its
  return value was introduced (older WordPress versions returned nothing).
- Used `wp_strip_all_tags()` in the plain-text caption fallback. The ordinary
  `wp_kses_post()` caption path is unchanged.
- Regenerated the translation template's source references and updated the
  1.16.1 changelog. Version and Stable tag are unchanged.
