## Issues found and corrected

1. Failed galleries could count as both completed and errored, advancing queue
   progress twice and finishing a multi-gallery run early. Option summaries,
   table aggregates, affected-turn counters and queue-transition validation now
   count a failed root once. The persisted checkpoint format is unchanged.
2. Gallery and album dialogs treated a finished queue containing errors as a
   successful 100% result. They now show a visible error message without the
   success meter. Image-tag sync also reports a completed run with errors as a
   failure in its dialog.
3. Compact saved galleries retain image-error messages without retaining their
   image objects. Their saved errors and Retry Migration control now remain
   visible after reloading, without loading the source image list.

Regression coverage includes mixed failure/success queues in option and table
paths, saved failed-root queue projections, the actual table aggregate predicate,
compact error rendering in both modes, escaping hostile saved messages, successful
retries, shared-dialog failure/success behavior and image-tag error results.

## Main-site caveat and release boundary

not proof of safe ownership takeover. They can still prevent a storage-mode change
on the main test installation; conversion and recovery were validated in the
separate owned installation. This deployment does not silently clear those
markers or alter the barrier's safety policy.

No v2 engine implementation, Git push, merge, WordPress.org tag publication or
Stable tag change is part of this work. Public release remains a separate step.
