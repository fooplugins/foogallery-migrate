# FooGallery Migrate 1.16.4 — main test-site cleanup and storage QA

Brad authorized clearing the three old writer markers, testing storage switching,
clearing history, resetting storage and performing full uninstall last on the
prepared main test site. No backup was requested. This report supplements
[the 1.16.3 results](1.16.3-test-results.md); its previous main-site marker caveat
is now resolved. No Git push, merge, public release or Stable tag change occurred.

## Writer markers

`StorageMaintenanceGate` creates a writer marker when it admits a migration-data
mutation. Normal request completion releases that marker. The three old markers
had last creation/renewal timestamps of 25 October at 09:50:04, 09:51:28 and
16:39:53 UTC. Their records contain no request action or caller identity. An
interrupted worker is consistent with their survival, but neither marker data
nor available access logs prove which migration, admin or CLI request left them.

Removal did not rely on expiry alone. The operator verified the exact three names
and value hashes, no queued/started migration and no competing database work,
then acquired the plugin's maintenance barrier. The site's PHP-FPM hard request
termination limit was confirmed as 90 seconds. After draining for 121 seconds
while renewing the barrier, the exact writer set and quiescence were checked
again. A value-guarded atomic delete removed exactly three markers. Fingerprints
confirmed posts, post metadata, migration options, 11 state heads and 10,761
records were unchanged. The owned maintenance barrier was then released.

This was a guarded operator repair of the test site. The plugin's automatic
writer ownership/expiry policy has not been weakened.

## Bug found and fixed

Clearing authoritative table-backed history left a legitimate empty state. The
Plugins tab then threw `Missing site state scope; no option fallback` instead of
allowing lazy source detection. Version **1.16.4** accepts a missing collection
when both the site heads and site records are absent. A bounded, site-scoped
record existence query still refuses orphaned records. Failed reads and a
concurrently created head still refuse; there is no fallback to stale options
and no implicit repository write.

Eleven regression cases cover empty/unrelated collections, lazy defaults, stale
option isolation, no writes, orphan rejection, all three SQL failure stages and
concurrent head creation. They fail against the previous implementation. The
fixed package was deployed, then both Clear Migration History and Reset were
retested through the normal UI, including a fresh Plugins page and lazy detection.

### Expected large-state reversal refusal

The original table state contained **22,329,441 encoded payload bytes**, including
21,838,687 bytes of migrated history. This exceeds the existing **16 MiB**
table-to-options conversion budget. The plugin correctly refused that reversal
and kept healthy, stable table authority with its data intact. The limit was not
raised or bypassed. Both switch directions were then tested successfully after
the authorized history clear reduced the state. A large site may need to clear
history before returning to option storage.
