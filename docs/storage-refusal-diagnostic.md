# Private storage refusal diagnostic

This is diagnostic-only instrumentation, not admission remediation, calibration approval or native success evidence. Public error codes/messages and response fields are unchanged.

The existing StorageScalarObserver private milestones_enabled switch also opts into one private refusal record. It is disabled by default and may only be armed/read through reflection by an external authorized harness in its own process. There is no request parameter, filter, constant, callback, public getter or persisted diagnostic. Complete current-site capability, exact request, confirmation and purpose-nonce authorization opens the recording scope; receiver entry and each authorization attempt clear old scope/records, including denied requests.

Only these exact scalar reason/phase pairs can be retained:

- raw-budget / conversion-budget
- decode-memory / conversion-budget
- scale-work / scale-tick
- scale-deadline / scale-tick
- scale-memory / scale-memory
- physical-census / retained-census

Record at the actual guard before masking. The first instrumented refusal wins; later cleanup cannot replace it. Invalid pairs are ignored. No exception text, stack, source values, keys, paths, hashes, bytes, IDs or arbitrary strings enter this record. An absent record is UNKNOWN, not evidence that any particular guard passed or fired. This finite diagnostic is not exhaustive arbitrary-hook or native-first-guard proof.

StorageRefusalDiagnosticTest reaches public recovery and real snapshot preflight with a small serialized source whose encoded snapshot exceeds the same unchanged raw cap. It checks the unchanged generic error, retained source/control, no staging/authority/backup writes, default-off, authorization and scalar no-leak behavior. Query/gate spies establish the reachable host path only, not native WordPress/SQL persistence or literal PHP runtime compatibility. Source and extracted production ZIP must run the same external harness. Original retaining failures remain independent and open.
